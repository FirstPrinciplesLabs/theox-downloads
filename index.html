A Study is a project

Every question grows its own scientific software

V2 begins without an inherited scientific registry. Each new Study creates or imports its own data, definitions, code, tests, evidence, discussion, and manuscript, so the result remains inseparable from the machinery that produced it.

  1. 01
    BuildDatasets, descriptors, simulations, packages, and tests evolve with the question.
  2. 02
    DiscoverPeople and agents conjecture, compute, visualize, search, and invent inside the same project.
  3. 03
    VerifyProofs, counterexamples, literature, and independent runs remain attached to each claim.
  4. 04
    ContinueA release can be reproduced exactly, then expanded into the next version of the science.

Models

Choose the intelligence for each part of the work

Bring provider keys, run a local model, or connect a self-hosted endpoint. The advisor can use one route while discovery, literature, and verification use others. Every contribution is attributed to its person, model, settings, and Study revision.

Model choice belongs to the researcher. Scientific custody remains with the Study.

Privacy

Decide where every model runs and what it can see

Local routes can keep model execution on the researcher’s hardware. Cloud routes receive only the context selected for that task. Collaboration synchronizes the versioned Study record without requiring every contributor to use the same provider.

Private work can remain private. Share a release only when the Study is ready.

Verification

A claim is only as strong as its surviving evidence

TheoX keeps conjectures, proofs, counterexamples, literature matches, computations, and failed attempts in one causal record. Verification is a process, not a badge: every status can be inspected, replayed, and challenged on a new machine.

The paper is a view. The Dynamic Research Object is the reproducible publication.
